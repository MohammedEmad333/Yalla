# 13 — المطاعم والطلب من القائمة (Restaurants & Menu Ordering)

صفحة **المطاعم** داخل تطبيق يلا (على غرار تطبيقات طلب الطعام): يختار الزبون
مطعمًا، تظهر له قائمة الطعام الخاصّة بالمطعم، يضيف الأصناف إلى سلّته، ثمّ يطلب
مباشرةً من التطبيق.

الفكرة المعمارية باختصار: **الطلب من مطعم هو طلب توصيل عادي** — نقطة استلامه هي
المطعم، ويحمل معه أصناف السلّة وأسعارها. لذلك يعمل معه كلّ ما هو مبنيّ أصلًا بلا
تكرار: التسعير بالمسافة، خصم المحفظة، الإسناد للكابتن (يدوي/تلقائي/بثّ)، التتبّع
اللحظي، الدردشة، رمز التسليم، والتقييم.

---

## 1) قاعدة البيانات

### `restaurants` — المطعم/المتجر
| الحقل | النوع | الوصف |
|------|------|------|
| `name`, `description` | String | الاسم والوصف |
| `category` | String | التصنيف (مشاوي، شاورما، بيتزا، حلويات...) — يُستخدم لرقائق الفلترة |
| `imageUrl`, `phone` | String | صورة الغلاف وهاتف المطعم |
| `city`, `neighborhood`, `street`, `address` | String | العنوان (`address` يُركَّب تلقائيًا) |
| `location` | GeoJSON Point | إحداثيّات المطعم — تُشتقّ من (المدينة + الحي) |
| `minOrder` | Number | الحدّ الأدنى لقيمة الطلب (₪) |
| `prepMinutes` | Number | زمن التحضير — يُضاف للزمن التقديري للتوصيل |
| `isOpen` | Boolean | مفتوح الآن؟ (المغلق يظهر بلا إمكانية طلب) |
| `active` | Boolean | مفعّل؟ (المعطّل لا يظهر للزبائن) |

### `menuitems` — صنف في قائمة مطعم
| الحقل | النوع | الوصف |
|------|------|------|
| `restaurant` | ObjectId → Restaurant | المطعم صاحب الصنف |
| `name`, `description`, `category` | String | الاسم والوصف والقسم داخل القائمة |
| `price` | Number | السعر بالشيكل — **مصدر الحقيقة** الوحيد |
| `available` | Boolean | متاح الآن؟ |

### `orders.store` — نسخة الطلب من السلّة
| الحقل | الوصف |
|------|------|
| `restaurant`, `name` | المطعم واسمه وقت الطلب |
| `items[]` | `{menuItem, name, price, qty, note}` — نسخة ثابتة لا تتأثّر بتعديل القائمة لاحقًا |
| `itemsTotal` | قيمة الأصناف (بلا أجرة التوصيل) |
| `note` | ملاحظة الزبون للمطعم |

يبقى `store` فارغًا في طلبات التوصيل العاديّة، ويُلخَّص محتواه نصًّا في
`packageNote` («مطعم يلا: 2× شاورما، 1× كولا — بلا ثوم») فيقرأه الكابتن ولوحة
الأدمن بلا أيّ تعديل في شاشاتهما.

## 2) الواجهات (API)

### عامّة (قراءة بلا مصادقة — مثل `/neighborhoods`)
| المسار | الوصف |
|-------|------|
| `GET /api/restaurants?city=&category=&q=` | المطاعم المفعّلة مع فلترة/بحث |
| `GET /api/restaurants/categories` | التصنيفات المتاحة فعليًّا |
| `GET /api/restaurants/:id` | مطعم واحد + قائمته مجمّعة بالأقسام |

### الزبون
| المسار | الوصف |
|-------|------|
| `POST /api/orders/restaurant` | إنشاء طلب من مطعم: `{restaurantId, items:[{menuItemId, qty}], dropoff, note?, scheduledAt?}` |

يدعم ترويسة `Idempotency-Key` كبقيّة الطلبات.

### الأدمن
| المسار | الوصف |
|-------|------|
| `GET/POST /api/admin/restaurants` | عرض/إضافة مطعم |
| `PATCH/DELETE /api/admin/restaurants/:id` | تعديل/حذف مطعم (الحذف يشمل قائمته) |
| `GET/POST /api/admin/restaurants/:id/menu` | أصناف القائمة/إضافة صنف |
| `PATCH/DELETE /api/admin/menu-items/:itemId` | تعديل/حذف صنف |

## 3) مسار الطلب (Flow)

1. الزبون يفتح تبويب **المطاعم** → يبحث/يفلتر بالتصنيف → يختار مطعمًا.
2. تظهر قائمة الطعام مجمّعة بالأقسام؛ يضيف الأصناف فيظهر شريط السلّة السفلي.
3. **إتمام الطلب**: يراجع السلّة، يختار عنوان التسليم (المدينة ← الحي ← الشارع ←
   التفاصيل)، فتُحسب **أجرة التوصيل** من موقع المطعم إلى عنوانه، ويرى المجموع.
4. عند التأكيد يتحقّق الخادم من: المطعم مفعّل ومفتوح، الأصناف موجودة ومتاحة
   وتابعة لهذا المطعم، بلوغ الحدّ الأدنى، ثمّ يحسب القيمة **من أسعار قاعدة
   البيانات** (لا من العميل)، وينشئ الطلب عبر خدمة الطلبات نفسها.
5. من هنا فصاعدًا هو طلب عادي: يظهر للأدمن/الكباتن، يُسنَد، يُتتبّع، ويُسلَّم برمز
   التسليم.

**المال:** أجرة التوصيل تُخصم من محفظة الزبون كأي طلب (لذا يجب أن يكفي رصيده)،
وقيمة الأصناف تُدفع للكابتن عند الاستلام (نموذج COD الحالي). ربط دفع قيمة
الأصناف بالمحفظة ممكن لاحقًا دون تغيير البنية (القيمة محفوظة في `store.itemsTotal`).

---

## 4) لوحة الأدمن

تبويب **المطاعم**: عمود بقائمة المطاعم (مع حالة مفتوح/مغلق/معطّل)، وعمود لتحرير
بيانات المطعم وإدارة أصناف قائمته (إضافة/تعطيل صنف/حذف). ما يُحفظ هنا يظهر فورًا
في التطبيق.

## 5) بيانات تجريبية

```bash
cd backend && npm run seed:restaurants
# أو داخل docker:  docker compose exec api npm run seed:restaurants
```

يُنشئ أربعة مطاعم بقوائمها (مشاوي/شاورما/بيتزا/حلويات) — آمن للتكرار.
